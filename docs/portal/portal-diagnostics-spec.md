# Інструментарій Самодіагностики та Самолікування Порталу
**Статус:** Концептуальна специфікація системи стійкості та сповіщень

🩺 1. Компоненти Самодіагностики (Self-Diagnostics Core)
Портал має вбудований фоновий сервіс-демон (наприклад, diagnostics.js), який кожні 5 хвилин тестує систему:
- Перевірка Бази Даних: Тестовий запит до Supabase/SQLite.
- Перевірка Зовнішніх API: Пінгування API Telegram, Viber, GitHub.
- Перевірка Дискового Простору: Моніторинг залишку памяті у Docker-контейнері.

🩹 2. Алгоритми Самолікування (Self-Healing Triggers)
При виявленні збоїв Портал намагається вилікувати себе сам перед тим, як бити на сполох:
- Збій підключення до БД: Автоматичне перепідключення до 5 разів з інтервалом у 10 секунд.
- Зависання Node.js: Автоматичний перезапуск контейнера на Cloud Run.
- Переповнення кешу: Автоматичний запуск скрипту очищення тимчасових файлів.

🚨 3. Система Сповіщень (Alerting System)
Якщо самолікування не допомогло, Портал миттєво шле сигнал тривоги у Телеграм/Вайбер ШІ-архітекторам для оперативного виправлення.

🛠️ 4. План дій для Конструктора:
- [ ] Створити модуль diagnostics.js у папці backend.
- [ ] Налаштувати інтеграцію з Telegram Bot API для відправки логів помилок у ваш чат.
- [ ] Додати сторінку /admin/health на веб-панель Порталу для візуального контролю здоровя системи.

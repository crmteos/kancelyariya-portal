# PROJECT_SPEC.md — Специфікація та Архітектура Проєкту «Портал Канцелярії»

> **Версія:** 1.0.0  
> **Статус:** Затверджено  
> **Бюджет:** $0 (100% Безкоштовний стек)  
> **Методологічна основа:** ROPE (Requirement-Oriented Prompt Engineering), AI Chains, Zero-Cloud Architecture.

---

## 1. Загальна Концепція та Мета (Goal)

### 1.1 Мета проєкту
Створення веб-порталу **«Канцелярія Української Імперії»** — інтерактивного, естетично оформленого інформаційного та художньо-історичного ресурсу для презентації структури, документів, ролей та діяльності Канцелярії.

### 1.2 Вхідні матеріали
Усі концептуальні напрацювання, тексти, ієрархія ролей та історично-концептуальні документи знаходяться в локальній папці проєкту:  
📁 `kancelyariya-portal/docs/`

---

## 2. Формалізовані Вимоги ROPE (Requirements)

### 2.1 Критерії Успіху (Success Criteria)
1. **Автономний статичний веб-сайт**: Сайт працює без будь-якої серверної бази даних чи платних хмарних сервісів.
2. **Інтерактивна структура Канцелярії**: Наочна візуалізація ієрархії ролей, відділів та функціоналу (реалізована через чистий HTML/CSS/JS або легкий UI-фреймворк).
3. **Модуль перегляду документів**: Можливість зручно читати та фільтрувати матеріали з папки `docs/` прямо у браузері.
4. **Хостинг на GitHub Pages**: Сайт публікується в 1 клік за безкоштовною адресою `username.github.io/kancelyariya-portal`.

### 2.2 Негативні Обмеження (Negative Constraints) — **СУВОРЕ ДОТРИМАННЯ**
* ❌ **ЖОДНИХ платних сервісів Google Cloud / Vertex AI / AWS / Azure.**
* ❌ **ЖОДНИХ платних API-ключів або підписок з автоматичним списанням коштів.**
* ❌ **ЖОДНОГО складного backend-сервера** (Node.js/Python server), який потребує платного хостингу. Усі дані зберігаються у вигляді статичних `.json` або `.md` файлів у репозиторії.
* ❌ **ЖОДНОЇ генеалогії «Enterprise-архітектури з мікросервісами»** — проєкт розгортається у найпростішому статичному веб-стеку.

## 3. Технічний Стек ($0 Budget Architecture)

| Компонент | Обране рішення | Вартість |
| :--- | :--- | :--- |
| **Хостинг та деплой** | GitHub Pages / Vercel (Hobby Tier) | **$0 / назавжди** |
| **Верстка та Стилі** | HTML5, CSS3 (Tailwind CSS via CDN) | **$0** |
| **Інтерактивність** | Vanilla JavaScript (ES6) | **$0** |
| **Збереження даних** | Статичні `.json` / `.md` файли у репозиторії | **$0** |
| **Локальне середовище** | VS Code + Live Server extension | **$0** |
| **ШІ-кодування (IDE)** | Continue / Roo Code + Безкоштовний Gemini API Key (Google AI Studio) | **$0** (в межах Free Tier) |

## 4. Розподіл Ролей Інструментів ШІ

1. **Блокнот / Головний Чат (NotebookLM / Claude / Gemini Chat)**:
   * **Роль:** Головний Архітектор та Методист.
   * **Завдання:** Створення та оновлення специфікацій, аналіз вхідних матеріалів у `docs/`, контроль дотримання $0 бюджету, генерація інструкцій для кодера.
2. **VS Code (з плагіном Continue / Roo Code)**:
   * **Роль:** Виконавець-кодер (Micro-Task Executor).
   * **Завдання:** Написання коду HTML/CSS/JS, створення файлів структури, локальне тестування.

---

## 5. Архітектура Пам'яті Проєкту

Для запобігання втраті контексту та виходу з ладу через перезапуск чатів, стан проєкту фіксується у двох керуючих файлах:

* **`PROJECT_SPEC.md`** (Цей файл) — незмінне ядро вимог, обмежень та стеку.
* **`PROJECT_STATE.md`** — динамічний журнал стану (що зроблено, які файли створено, який наступний крок).

## 6. Покрокова Дорожня Карта Розробки (AI Chains Roadmap)

* **Етап 1: Впорядкування джерел та форматування даних**
  * Перетворення матеріалів з `docs/` у структурований JSON-файл `chancery_data.json` (список відділів, ролей та документів).
* **Етап 2: Створення верстки та дизайну (HTML/CSS)**
  * Створення головного шаблону `index.html` з естетичним оформленням Канцелярії (стильний темний/класичний дизайн).
* **Етап 3: Додавання інтерактивної картографії/структури**
  * Реалізація навігації по ролях та відділах Канцелярії на JavaScript.
* **Етап 4: Публікація на GitHub Pages**
  * Ініціалізація Git, завантаження на GitHub та активація безкоштовного хостингу.
